# DSH 任务管理插件 — 完整需求说明书

> 文档编号：DSH-TASK-REQ · 版本：V1.0 · 日期：2026-11-14
> 适用范围：在 DeepSeek Harness（DSH）中作为独立 Web 插件实现个人项目任务管理。
> 配套执行规范：《01-DSH任务管理插件-分析开发测试规范.md》。
> 状态：**可用于需求评审与开发准备；具体 DSH 适配 API、存储实现及 Super Productivity 版本兼容范围须在源码分析阶段验证**。

## 1. 产品定位与目标

构建一个 **DSH 原生、离线可用、面向个人的多项目任务管理插件**，参考 Super Productivity 的任务组织体验，但不复制其整套时间管理产品。

目标：
1. 用户可以在多个项目之间记录、拆分、安排和跟踪任务。
2. **同一份任务数据**以「列表 / 看板 / 艾森豪威尔四象限」三种形式展示，任一视图更新后其他视图立即一致。
3. 支持一级主任务和一级子任务，保留父子关系、顺序、独立完成状态和完成进度。
4. 支持 DSH 自有 JSON 数据备份/恢复，以及对可确认版本的 Super Productivity JSON 进行安全导入。
5. 与 DSH 现有导航、配色、插件生命周期、存储及安全边界一致；卸载不破坏 DSH 核心。

### 1.1 不在范围内（明确禁止自行加回）

- **不做**「今日任务」或跨项目的每日计划模块；不设置 TODAY 特殊标签或自动聚合。
- **不做**独立 Backlog/任务池、收件箱、未计划队列；每条任务必须属于一个明确项目。
- **不做**任务计时、开始/暂停、番茄钟、工时统计。
- **不做**周期任务或每日/每周自动生成任务。
- **不做**多人协作、账号注册、远程云同步、手机 App、提醒推送、日历排程。
- **不做**把 DSH Agent 的执行轨迹自动当成任务；Agent 写入任务列为后续可选能力（P2），V1 不依赖。
- 不照搬 Super Productivity 无关的配置、指标、计时、标签体系；无法映射的数据不能静默变成 DSH 功能。

### 1.2 用户与核心场景

- 用户主要在本地 DSH Web 界面使用；可能处于不可登录、不能访问外网的公司内网。
- 同时管理如 DSH 开发、LocalPM、技术学习等彼此独立的项目。
- 希望 **快速录入 → 分类 → 处理 → 完成**，无需复杂的每日排期。
- 需要将 Super Productivity 的现有项目和任务迁移过来，但不暴露个人 JSON 给第三方。

## 2. 术语与优先级

| 术语 | 定义 |
|---|---|
| Project | 用户定义的任务容器；项目与 DSH 的代码工作区/聊天 Session **不是同一个概念** |
| Parent Task | 顶层任务，可以包含若干子任务；在看板/四象限上是一张卡片 |
| Subtask | 隶属于某个顶层任务的二级任务；有独立状态，不独立出现在看板/四象限列中 |
| Status | 流程状态：待办（todo）、进行中（doing）、完成（done） |
| Quadrant | 四象限，由 important 和 urgent 两个布尔值唯一计算得出 |
| Scope | 当前项目 / 所有项目过滤范围；对三个视图都生效 |
| P0 | 上线必须具备；任何 P0 未经验证通过，不能宣布版本完成 |
| P1 | 后续体验迭代，不阻碍 P0 交付 |
| P2 | 可选未来扩展，不在当前承诺范围 |

## 3. 总体信息架构与导航

**REQ-001｜独立插件入口｜P0**
- 在 DSH 当前 Web Profile 中安装后，提供「任务管理」可发现的稳定入口；优先使用 DSH 官方导航/Slot API。
- 插件独立于聊天 Session：切换会话、关闭会话或清空聊天，不得删除或隐藏任务数据。
- 禁用/卸载插件后 DSH 核心其他功能正常；重新启用后原有数据仍在（除非用户显式删除插件数据）。
- 若当前 DSH 版本不支持预期注册点，应采用官方支持的替代扩展点并记录差异，不得私自改核心源码。

**REQ-002｜整体布局｜P0**
- 主界面由「项目导航」「任务工作区」组成，详情为按需打开的右侧面板/抽屉（窄屏改覆盖层）。
- 左侧上方显示全部任务入口；「看板」目录包含看板与四象限，「项目」目录包含项目链接，两个目录独立展开/折叠。归档入口收进项目「…」菜单；视图与项目分别显示当前选中态。
- 工作区顶部显示当前视图标题和「…」菜单，导入导出收进该菜单，新建任务「＋」入口保持可见，输入按需展开，支持 Shift+A、Enter 和 Esc；看板和四象限切换保留当前项目范围及状态筛选；全部任务入口返回跨项目列表并重置筛选，点击项目直接进入该项目的任务列表。
- 目录折叠不改变右侧当前项目或视图；展开状态作为浏览器本地偏好保存，刷新后恢复。
- 空项目、加载中、错误、导入中分别显示清晰状态，禁止静默空白。
- UI 沿用 DSH 亮暗表面与字体，参考 SP 使用蓝色强调色、轻边框和内容分块；支持浅色/深色模式、中文文案；不得强迫另开浏览器应用。

2026-11-14 视觉补充：任务行、卡片密度与按需操作参考用户本机 Super Productivity。列表采用紧凑横向任务行；看板采用浅层背景与轻边框卡片。辅助信息合并为一行，默认待办和 Q4 不常驻贴标签；非默认状态、象限用轻量标签呈现。状态、象限和排序都可在任务菜单操作，子任务进度只显示一次。功能和数据规则沿用本需求，详见 `UI-DESIGN.md`。

**REQ-003｜范围切换｜P0**
- 当前项目：仅查询这个项目未归档的任务。
- 所有项目：跨全部未归档项目展示任务，但**不是「今日任务」**；每个任务显示项目名。
- 列表、看板、矩阵具有相同的 Scope；切换视图不更改任务数据。
- 范围筛选只影响可见结果，不移动任务、不复制任务。

## 4. 项目管理

**REQ-010｜项目增删改查｜P0**
- 创建：名称必填，去除首尾空格，空名不允许；相同名称可由产品明确选择拒绝（V1 决定：**同名不允许**，不区分大小写）。
- 修改：名称、可选描述、排序；名称修改后所有任务以项目 ID 关联，不能丢失归属。
- 项目列表支持手动排序并持久化。
- 删除：必须确认并展示关联任务/子任务数量；确认后整组操作以单事务处理，失败回滚，不产生孤儿任务。
- 归档：项目从默认活动列表中隐藏，关联任务保留；可从「已归档项目」恢复；已归档项目的任务在默认「所有项目」中不展示。
- 不提供系统默认隐式项目、Backlog、收件箱。创建任务前必须选定现有项目；首次使用时展示「创建第一个项目」。

**REQ-011｜项目删除保护｜P0**
- 删除含任务的项目必须出现明确的不可逆风险提示（项目名、主任务数、子任务数）；需要二次确认。
- 删除/归档项目时不得修改其他项目任务。
- 对不可恢复的删除需提示先导出备份；实现方式可采用事务性逻辑删除，但 UI 行为必须一致且不能虚称提供恢复入口。

## 5. 任务与任务详情

**REQ-020｜任务 CRUD｜P0**
- 任一项目列表可新建任务；只强制填写标题，`projectId` 由当前项目自动填写，或在所有项目范围选择项目。
- 标题非空（trim 后），建议最大 200 字符；超过上限显示校验，不截断静默保存。
- 可编辑标题、描述、备注、所属项目、状态、优先级、截止日期、重要性、紧急性。
- 支持单个删除；若包含子任务，确认框应显示子任务数量，主任务和子任务按原子操作一起删除。
- 同一任务 ID 唯一；一次操作不得重复生成任务。
- 创建成功后立即在统一数据源中生效，页面刷新后保持。

**REQ-021｜默认值｜P0**
- `status = todo`（待办）。
- `important = false`，`urgent = false`，所以默认落入 **Q4：不重要、不紧急**；无「未分类」象限。
- `priority = normal`（普通，可编辑；与四象限互不影响）。
- 截止日期为空；描述/备注为空；排序追加到当前分组末尾。
- `createdAt/updatedAt` 为系统时间，由持久层生成。

**REQ-022｜任务状态｜P0**
- 状态只取 `todo / doing / done` 三值；任何状态都允许手动切到其他状态。
- 完成任务仅更改该任务 `status`，不自动删除、不清空截止日期或四象限。
- 已完成任务可恢复至「待办」；完成/恢复保存时间信息（至少 `completedAt`：完成时记录，恢复时清空）。
- 每次从未完成变为完成时记录本次完成时间；修改已完成任务的标题、备注或排序不刷新该时间，取消后再次完成则记录新时间。列表和详情显示本地完成时间，导入的估算时间明确标注估算。
- 不以是否正在计时推导「进行中」。

2026-11-14 状态简化：取消阻塞功能。旧版持久化快照和原生备份中的 `blocked` 迁为 `todo`，保留任务及父子关系、归档、备注和排序；新编辑与拖拽请求不得再设置 `blocked`。迁移保存失败时停止插件启动，不提供未落盘的新状态。

**REQ-023｜任务详情｜P0**
- 点击任务标题/卡片打开详情；编辑描述与备注，显示状态、项目、优先级、截止日期、四象限、创建/修改时间及子任务。
- 正文支持多行纯文本/安全的轻量格式；输出必须安全处理，不能通过任务内容注入脚本。
- 详情面板关闭再打开，保留已成功保存的更改；编辑中有未提交变更时不得静默丢弃（采用显式保存或经过验证的自动保存策略并提示）。
- 详情采用按内容分块的面板；编辑后防抖及失焦自动保存，关联操作前先完成保存。仅提交实际编辑字段，冲突保留输入；浏览器本地保存未落盘草稿，重开同一任务可恢复，保存成功后清理。
- 截止日期为日期字段，不做提醒、日历或时区排程；无效日期拒绝。

**REQ-024｜排序｜P0**
- 列表中的未完成任务可手动排序；已完成任务按完成时间从早到晚自动排列在底部，不提供手动排序。看板同列卡片排序、四象限同象限卡片排序均需持久化。
- 一个视图内调整顺序，不应无意中重排其他视图；逻辑模型可使用各视图独立 `order` 值。
- 拖拽失败时恢复原位置并提示；提供非拖拽操作（如上移/下移）以支持键盘与触屏。

## 6. 子任务

**REQ-030｜父子结构｜P0**
- V1 支持 **两级结构**：主任务 → 子任务，禁止子任务继续添加子任务；出现不支持层级时明确告知。
- 每个子任务具有独立 ID、标题、描述/备注（可选）、状态、截止日期（可选）、排序位置； `parentId` 指向主任务。
- 子任务 `projectId` 必须与主任务一致；父任务移动项目时全部子任务原子迁移。
- 禁止循环关联、孤儿子任务、一条子任务挂多个父任务、跨项目不一致。
- 主任务菜单提供行内添加子任务：回车创建，Esc 退出；保留详情中的创建入口。
- 子任务创建后在任务列表中直接显示为缩进任务行，并标明所属主任务，可点击归属标识打开主任务；列表默认展开子任务，允许手动折叠。
- 子任务列表有编辑、删除、勾选完成、排序、展开/折叠。

**REQ-031｜子任务状态规则｜P0**
- 子任务与父任务的 `status` **互相独立**：勾选子任务完成，不自动完成父任务；完成父任务，也不强制完成未完成的子任务。
- 父任务显示 `已完成子任务数/子任务总数`，如 `1/3`；主任务自身的完成状态不计入这个比值。
- 父任务进度显示 `N/M`，零子任务时不展示 `0/0`；完成的子任务可以恢复未完成。
- 同一父任务下，未完成子任务在前，已完成子任务按完成时间从早到晚排在末尾；父任务自身的状态保持独立。
- 默认子任务不单独在看板/矩阵形成卡片；它跟随主任务出现在项目、状态列和象限中。
- 子任务的象限**继承父任务卡片**，V1 不提供独立子任务矩阵归类；子任务的状态可以独立编辑，不应移动父卡片的看板列。

**REQ-032｜子任务导入和移动｜P0**
- 导入时先建立 ID 映射，再恢复父子引用和原始相对顺序；不可按标题合并。
- 不能产生重复子任务、错误项目归属或无声丢失的层级关系。
- 主任务跨项目移动，子任务一起移动；不允许只移动单个子任务去另一个项目。

## 7. 三种视图及数据流

**REQ-040｜统一数据源｜P0**
- 所有视图通过同一 Task Repository/Service 进行查询和修改；不能将看板和矩阵分别作为独立真相源。
- 任一视图提交成功，应即时更新订阅视图；刷新或 DSH 重启后从持久层恢复一致状态。
- 操作失败，前端应回滚乐观更新（如采用），显示具体可理解错误，绝不假装成功。
- 删除、归档和跨项目操作对所有视图即时一致；不保留幽灵卡片。

**REQ-041｜列表视图｜P0**
- 单项目列表中，未完成主任务在前并保留手动顺序，已完成主任务按完成时间从早到晚沉底。全部任务显示连续任务列表，标明每条任务的所属项目；右侧不提供项目折叠分组，未完成任务在前、完成任务按完成时间从早到晚沉底。
- 每项可标记完成、改状态、打开详情、展开子任务、移动排序。
- 子任务以缩进和进度展示，不重复成为顶级列表项。
- 默认显示所有状态；完成任务采用清晰但不刺眼的视觉区分；可以通过状态筛选（基础状态筛选 P0）。

**REQ-042｜看板视图｜P0**
- 三列固定为「待办」「进行中」「完成」；列标题带可见数量。
- 只展示主任务卡片；每张卡片显示标题、项目（全部项目模式）、优先级/截止日期（若有）、子任务进度。
- 将卡片拖入另一列仅修改 `status`；不得修改 `important/urgent`、`projectId` 或子任务状态。
- 允许同一列拖动排序；空列正常显示；较多任务时各列可独立滚动（具体 UI 按 DSH 规范）。
- 拖拽不可用时，卡片菜单可显式选择状态。

**REQ-043｜艾森豪威尔矩阵｜P0**
- 四象限固定：
  - Q1：重要且紧急（important=true, urgent=true）；
  - Q2：重要不紧急（true, false）；
  - Q3：不重要但紧急（false, true）；
  - Q4：不重要不紧急（false, false）。
- **新建任务默认 Q4**；无第五个「未分类」象限。
- 每个象限只展示主任务卡片；卡片显示项目（全部项目模式）、非默认状态和子任务进度。默认待办不重复贴标签，状态可从任务「…」菜单查看和修改。
- 象限间拖动，仅更新两个布尔字段；不更改看板状态、项目和子任务状态。
- 默认矩阵显示未完成任务，提供「显示已完成」开关；已完成任务不会因完成而丢失象限属性。
- 同象限内支持排序，且不影响看板列的顺序；不能拖拽时可从菜单选择象限。

**REQ-044｜跨视图一致性范例｜P0**
1. 在项目 `DSH` 中创建任务 `开发任务插件` → 状态为 `todo`，看板出现在「待办」，矩阵出现在 Q4。
2. 从看板拖至「进行中」 → `status=doing`，矩阵仍在 Q4。
3. 从矩阵拖至 Q1 → `important=true, urgent=true`，看板仍在「进行中」。
4. 添加两个子任务、完成一个 → 各主任务卡片显示 `1/2`。
5. 将主任务移至 `LocalPM` → 项目、列表、看板、矩阵和子任务归属全同步。
6. 刷新、切换 DSH 会话、重启 DSH → 所有以上变化仍正确。

## 8. JSON 导入、导出与安全迁移

**REQ-050｜DSH 原生 JSON 导出｜P0**
- 用户可导出 **当前全部插件数据**（活动与已归档项目、任务/子任务、状态、矩阵、排序、描述、时间戳、schemaVersion）；导出为 UTF-8 JSON。
- 导出内容包含清晰的 `format`、`schemaVersion`、`exportedAt` 元数据；不会包含 DSH 会话、API Token、账号凭据或其他插件数据。
- 导出再导入可无损恢复受支持的 DSH 任务字段和关联；版本变更必须提供显式迁移或拒绝并说明。

**REQ-051｜DSH 原生 JSON 导入｜P0**
- 支持选择本地文件（不上传云端），先解析、校验、预览项目/主任务/子任务数量与冲突，再要求用户确认导入。
- 默认模式：**合并导入**，不覆盖已有任务；对已导入且来源 ID 相同的数据执行幂等去重，显示新增/跳过数量。
- 若未来支持「替换全部」，必须单独高风险确认、自动导出安全备份；V1 **不提供替换全部模式**。
- 导入期间禁用重复提交；失败必须事务回滚；不能产生部分导入数据。

**REQ-052｜Super Productivity JSON 导入｜P0（限定兼容范围）**
- 可接受官方确认的完整状态原始 JSON，或含 `data`、版本/时间包装字段的 JSON；严格按已验证的版本结构选择适配器，不采用臆测的字段路径。
- 识别项目、活动任务、子任务、完成状态、描述/备注、顺序、截止日期等**已验证字段**；对无法确认的字段逐项报告为「未支持」，不擅自推导。
- `isDone=true` 映射 `done`，`false` 映射 `todo`；不能凭 Super Productivity 的计时数据推断 `doing`。
- 重要性/紧急性若无可证明的源字段，导入均默认 `false`；不能根据优先级或标签擅自分类。
- 完整验证 `projectId`、`parentId`、`subTaskIds` 的一致性（若某版本存在这些字段）；按 ID 引用映射，不按标题猜测父子关系。
- SP 中的今日规划、Backlog、计时、周期任务、插件配置等不生成对应 DSH 模块。属于活动项目的未完成任务不能因为原来在 Backlog 中就被**无声丢弃**：按实际任务所属项目导入或明确列入导入报告；找不到合法项目的任务不能偷偷进入默认项目。
- 已归档历史、第三方插件配置、提醒等不在首版完整映射范围；**必须在预览中列出被跳过的实体数量及原因**。有数据丢失风险时先提示，允许取消。
- 不保证对所有历史版本兼容：未知版本、不完整快照、严重结构错误时拒绝导入并显示原因；不得将转换成功等同于完成真实性验证。
- 导入不改写源文件；保留原始 ID 的来源引用、对本地 ID 安全重映射；重复导入同一文件不会生成重复项目/任务。

**REQ-053｜导入预览与诊断｜P0**
- 预览至少显示：来源格式/版本、活动项目数、活动主任务数、子任务数、完成数、归档数、跳过数、错误/警告、潜在冲突。
- 完成后显示：新增/跳过/失败条数、映射结果、错误摘要；可复制/导出无敏感内容的诊断摘要。
- 文件不是合法 JSON、结构不支持、引用断裂、重复 ID、异常大文件、意外字段类型时明确失败并保持原数据不变。
- 防止 JSON 原型污染、意外脚本执行；设置合理的大小/记录数上限，由实现阶段根据压力测试确定并写入 UI 文案。

### 8.1 关于公开格式的来源约束

- 官方说明：完整备份是应用模型快照，可能是原始完整状态或含 `data/timestamp/crossModelVersion` 等包装；通过 ID 维护实体关系。官方还提醒它是明文 JSON。
- 官方 API 文档表示主任务与子任务最多两级；子任务从父任务继承 `projectId`，修改父任务项目会一起迁移子任务。**这些是公开 API 行为参考，不等于所有历史导出 JSON 都使用相同结构**。
- 导入适配器必须以当前官方源码、可核验的公开样本和自动化测试为依据。未经证实的包装字段、版本兼容性和字段含义一律标注待核实。

## 9. 非功能需求

**REQ-060｜本地与数据边界｜P0**
- 无网络仍可创建、编辑、查询、拖动、导出、导入和重启恢复任务；不要求登录任何账号。
- 数据归 DSH 任务插件独立管理，不与聊天 Session 生死绑定；存储目录遵循 DSH 当前规范，不在用户工作区隐式写文件。
- 默认不向网络发送任务内容；如底层组件发起外部请求必须关闭或明确说明。
- 单机单用户先行；并发编辑要避免静默覆盖，使用事务/版本检查或经验证的事件顺序处理。

**REQ-061｜可靠性｜P0**
- 所有写操作成功才展示已保存状态；重复点击、刷新、进程异常中断不能损坏数据库。
- Schema 升级需要可测试的迁移路径、版本校验和失败回滚；不能因插件升级直接清库。
- 空态、损坏文件、存储不可写、导入失败、插件加载失败均有可操作的错误信息。
- 常规日志不打印任务描述全文或导入原始数据；诊断日志避免泄露私密内容。

**REQ-062｜性能与易用性｜P0**
- 以至少 2,000 个主任务、5,000 个子任务、20 个项目进行离线压力验证；记录加载时间、过滤、拖拽更新和内存指标。目标：正常机器操作不明显卡顿，界面应采用必要的分页/虚拟列表，不能锁住 DSH 主 UI。
- 所有关键操作有可见反馈；拖拽有清晰落点；选中、聚焦、悬停、完成状态符合 DSH 视觉体系。
- 支持键盘完成核心操作，至少：新建任务、打开/关闭详情、改状态、触发非拖拽象限移动。

**REQ-063｜可扩展性｜P1/P2**
- P1：搜索与组合筛选、统计概览、批量操作、丰富键盘快捷键、数据量大的性能优化。
- P2：提供受权限约束的 Agent 查询/创建/修改接口；不能绕过统一任务服务或直接写数据库。
- V1 数据模型应保留兼容升级能力，但**不得提前实现**未获确认的功能。

## 10. 逻辑数据模型（实现需结合 DSH 宿主确认）

以下为逻辑契约，非强制要求使用特定数据库表名或 ORM：

```ts
interface Project {
  id: string;
  name: string;
  description?: string;
  order: number;
  archivedAt?: string | null;
  createdAt: string;
  updatedAt: string;
}

type TaskStatus = 'todo' | 'doing' | 'done';
type TaskPriority = 'low' | 'normal' | 'high';

interface Task {
  id: string;
  projectId: string;
  parentId: string | null;    // null = 主任务；非 null = 二级子任务
  title: string;
  description: string;
  notes: string;
  status: TaskStatus;
  priority: TaskPriority;
  important: boolean;        // 主任务默认 false；子任务使用父卡片象限
  urgent: boolean;           // 主任务默认 false；子任务使用父卡片象限
  dueDate: string | null;    // YYYY-MM-DD，不含时刻
  listOrder: number;
  boardOrder: number;
  matrixOrder: number;
  completedAt: string | null;
  createdAt: string;
  updatedAt: string;
  source?: { system: 'dsh' | 'super-productivity'; externalId?: string };
}
```

**强制不变量：**
- 每个 Task 的 `projectId` 必须指向存在的项目。
- `parentId` 不为空时，必须指向同项目顶层任务；不允许再嵌套或自引用。
- `important` 和 `urgent` 仅可为 boolean，禁止 null/undefined 入库；创建默认 false/false。
- `status=done` 时 `completedAt` 非空，其他状态为 null（历史导入若不提供准确完成时间，按导入时间标记并标记来源，或以明确设计策略处理；不可假装历史真实完成时间）。
- 卡片视图只枚举 `parentId=null` 的任务；子任务仅在父任务内显示。
- 项目/任务 ID 为稳定主键；重命名不会创建新 ID；导入来源 ID 不应直接覆盖本地 ID。
- 所有涉及父子关系的变更需在同一事务完成。

## 11. 操作、展示及异常规则表

| 用户操作 | 统一数据变更 | 列表 | 看板 | 四象限 |
|---|---|---|---|---|
| 项目新增主任务 | 新 Task(todo,false,false) | 当前项目出现 | 待办列出现 | Q4 出现 |
| 看板拖到进行中 | status=doing | 状态改变 | 移列 | 象限不变 |
| 矩阵拖到 Q1 | important=true; urgent=true | 重要/紧急标识更新 | 列不变 | 移至 Q1 |
| 子任务勾选完成 | 该子任务 status=done | 父任务进度 +1 | 父卡片进度 +1 | 父卡片进度 +1 |
| 完成父任务 | 父任务 status=done | 显示已完成 | 完成列 | 默认隐藏，可切换显示 |
| 主任务切换项目 | 父子 projectId 原子改变 | 原项目消失/目标出现 | 目标范围出现 | 目标范围出现 |
| 项目归档 | archivedAt 设置 | 活动列表隐藏 | 活动范围隐藏 | 活动范围隐藏 |
| 导入同份备份两次 | 第 2 次不重复创建 | 无重复 | 无重复卡片 | 无重复卡片 |
| 持久化失败 | 事务回滚 | 恢复旧值且提示 | 恢复原列 | 恢复原象限 |
